## 一、我们的方法背景

我们独立提出了一套基于哈密顿路径边结构分析的注意力增强框架，将注意力图分解为四种边类型：虚拟边、真实边、残缺边与弯曲边。

其中"虚拟边"的定义是：相距较远、但语义或相位相近的单元之间，直接建立长程捷径连接。信息沿捷径直接注入目标位置，不沿序列逐层传递。近邻细节由独立的滑动窗口分支负责，虚拟边只做远距离选择，构成近远分工。

该方法的完整描述、数学公式与参考实现见附件论文《面向超长上下文的大型语言模型：基于哈密顿路径虚拟边结构的注意力增强方法》（Qwen2.5-0.5B 与 Qwen2.5-7B 实测）。

## 二、在 DeepSeek V4 公开实现中观察到的对应机制

DeepSeek V4 系列公开了推理代码（Hugging Face 仓库 deepseek-ai/DeepSeek-V4-Pro，MIT 协议，inference/model.py）与论文（arXiv:2606.19348）。其 Lightning Indexer（稀疏注意力索引器）机制与上述"虚拟边"在三个层面高度一致：

**1. 打分判据：语义相似度 × 位置相位对齐**

公开代码中，索引器的查询与压缩后的键值两端都应用了旋转位置编码（RoPE）相位：

- model.py 中索引器 query 应用 RoPE（部分维度）
- 压缩 KV 也按块位置取 RoPE 相位
- 打分 = 语义内积 × 相位对齐程度（旋转差小则得分高）

RoPE 的多频段结构使远距离位置对在特定距离处相位重新对齐（例如约 62k、125k、188k 距离处出现共振峰），从而"远处但相位相近"的块获得高分。这是周期性的距离依赖，不是单调的"越近越好"偏好。

**2. 建边方式：top-k 稀疏 + 近邻分流**

- 按索引打分取 top-k（index_topk=1024）个远距键建边
- 近邻由独立 SWA 滑动窗口分支负责
- 与"虚拟边只做远距选择、近邻归独立分支"的结构一致

**3. 官方模型自述（公开 API 实测原话）**

在公开 API 上就代码设计意图提问，官方模型的原话包括：

- "把 RoPE 的周期共振当成一种无参数的位置哈希/远程寻址机制"
- "确实建立了一条从远距离块到当前位置的捷径：信息不经过逐层传递，而是通过稀疏路由直接注入当前计算"
- "等价于一种数据无关的远程稀疏连接模式，连接距离由 RoPE 的周期共振决定"
- "滑动窗口 = 局部边；CSA 稀疏 = 远距离相似节点捷径边；HCA 重度压缩 = 图粗化/多尺度聚合"

这些表述与"虚拟边"机制的核心描述基本一致。

## 三、行为层面的客观观察

我们对 DeepSeek V4 系列进行过长程信息定位实测（公开 API，2026-08-03 至 08-12 共五轮，最后一轮完全复测一致）：

- 在 90K、128K、160K、200K 等远距离点位，单针与跨距双针任务全部命中
- 128K 及更远距离未观察到随距离增大而出现的性能陡降

该结果与"长程信息经相位对齐捷径直接跳跃、不沿序列逐层传播"的机制预期一致。我们同样指出附件论文中的诚实边界：超长上下文验证需在目标模型侧复现，本观察仅为行为层面的间接证据。
