# 哈密顿路径求解器·可复现数据包（2026-11-07）

一句话：给你一张真实世界建出来的图、一个求解器、两个独立写的校验程序，以及一条命令。你可以在自己的电脑上把"每个点恰好走一次、每一步走的边都真实存在"这条路自己复算一遍，不需要联网、不需要授权、不需要我们的任何配合。

## 二、三步跑完

先核对哈希（Windows PowerShell）：

```powershell
Get-FileHash -Algorithm SHA256 (Get-ChildItem -Recurse -File -Exclude SHA256SUMS.txt)
```

或者用 Windows 自带的命令行工具逐件核对（Git Bash 里一条命令核完全包）：

```text
sha256sum -c SHA256SUMS.txt        →  每行应打印 OK
```

对照 `SHA256SUMS.txt`，任何一件不一致就说明包被改动过，请向我们要原始包。

两个求解器二进制是同一份源码的两种编译方式，我们对拍过：同一张 20,000 点随机图、同一种子、同一时间预算，两者输出的路径**逐字节相同**（sha256 前 12 `9f5b7724a060b78754e7`），日志里的判定字段（pass／breaks0 11→0／size／rot 382／defects 0／mech）也逐字段相同，只有秒数差 0.4 秒以内。这条对拍您在自己机器上也能重跑：

```text
bin\dump_ba_edges_static.exe 20000 5 42 e20k.txt
bin\v23_static.exe     20000 5 42 120 --edges e20k.txt --out p1.txt
bin\v3x_m1v2_v23.exe   20000 5 42 120 --edges e20k.txt --out p2.txt    （需 MinGW 运行库）
```

求解（约 20 分钟内结束，普通笔记本，无 GPU）：

```text
bin\v23_static.exe 197888 5 42 1200 --edges data\edges_world.txt --out data\path_world.txt --jsonl data\run_world.jsonl
```

四个数分别是：顶点数、占位参数（因为给了 `--edges`，第二项不参与建图）、随机种子、时间预算秒。

**一句实话**：引擎的修复阶段是按墙钟切窗口的，所以换一台机器、换一个负载，最后得到的路径不保证和我们那条逐字节相同。可复现的是"同一条命令跑下去，用两个校验程序复核，看它是不是严格解、不是的话还剩几处没接上"；不可复现的是路径本身的字节序列，以及秒数（我们只把秒数当量级，不当结论）。本轮我们自己的那条路径已随包附上（`data/path_world.txt`），它的哈希与判定见 §三。

判定（两个校验程序各自独立复核，退出码 0＝通过）：

```text
python tools\verify_path.py  --edges data\edges_world.txt --path data\path_world.txt --N 197888
python tools\verify_path2.py --edges data\edges_world.txt --path data\path_world.txt --N 197888
```

第二张图（30,829 点，档案在册的历史那一档，本机现约 6 秒走完全链）。这四条命令从源 zip 一路推到校验，不需要我们任何配合：

```text
python tools\真实实例装载-v1.0-20261028.py delaunay --src data\cities500_10-28源包.zip --out e30k.txt --min-pop 500 --largest
bin\v23_static.exe 30829 5 42 1200 --edges e30k.txt --out p30k.txt --jsonl r30k.jsonl
python tools\verify_path.py  --edges e30k.txt --path p30k.txt --N 30829
python tools\verify_path2.py --edges e30k.txt --path p30k.txt --N 30829
```

第一条应打出 `DONE delaunay N=30829 E=92470`，且 `e30k.txt` 与随包的 `data\edges_30k_archived_recipe.txt` **逐字节相同**（sha256 前 12 `5a5b2ab5a11f`）——建图规则本身可复现，不只是一条命令的产物可复现。第二条 3 秒出解（`PASS size=30829 breaks 0->0`），随包路径 sha256 前 12 `95388f904a20`，静态件与在册动态件在这张图上也逐字节相同。
**这一档的筛选口径要说清楚**：脚本里写的过滤项叫"人口≥500"，但它读的是 GeoNames 第 14 列，那一列在这份快照里是行政区码而不是人口（人口在第 15 列）。所以这张 30,829 点的图实际上是"有行政区码且码值≥500 的城镇"，其中法国 15,280／德国 11,929／比利时 2,254，合计约 95.4%。它是一个真实的城镇图，但**不是全球均匀抽样**；全球口径（真读人口列）得到的正是本包主档那张 197,888 点、覆盖 242 个国家与地区的图。我们把两张都放进包里，就是为了这个错位能被您一眼看到。

**先跑这两个校验程序自带的负面对拍**，确认它们不是"什么都判通过"的空壳：

```text
python tools\verify_path.py  --selftest     →  SELFTEST=PASS
python tools\verify_path2.py --selftest     →  SELFTEST=PASS
python tools\check_obstacles.py --selftest  →  4/4 PASS
```

每一件事都插了五种坏答案（少一步、走一条不存在的边、同一个点走两遍、缺点、越界编号），必须全部被抓出来才算校验程序上岗。

## 五、能做什么、不能做什么

**能做**：给图 → 给出一条路径 → 两个独立程序复核这条路径是否"不漏、不重、步步真边"。同一套程序在四类输入上都有过实测：真实城镇坐标图、公路网、社交/邮件网络、随机网络模型。

**不能做，四条硬边界**：

1. 没有解决哈密顿路径问题，没有任何 NP 类结论。这里只有算法实现和它的实测耗时。
2. 一张图的结果不代表另一张图。稀疏图上有真实的形状障碍：档案里有两档（234,191 点、770,689 点）到最后分别还剩 2 处、9 处没接上；另一档（100 万点、平均每点连约 10 条线）在 3,600 秒预算内没清完，剩 521 处。
3. "无解"要有证书才能说。本包 `tools/check_obstacles.py` 就是那个证书工具：公开真实图里我们查了 8 张，7 张可以在开算之前证明根本没有哈密顿路径（比如一张加州公路网有 315,241 个只连一条线的端点，而一条路径只有两个端点名额）。这不说明求解器强弱，只说明问题本身无解。
4. 全部读数在普通个人电脑上产生，单机、无集群、无 GPU。换机器会有秒数差，我们只用秒数作量级，不用它作结论。
