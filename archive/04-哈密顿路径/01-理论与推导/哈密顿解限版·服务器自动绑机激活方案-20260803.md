## 一、架构（基于验证销毁方案v2 + 落到解限版EXE）

```
哈工大机器            华为云 yunshao-ai.icu
┌─────────────┐   POST /api/v1/activate   ┌──────────────┐
│ 解限版EXE    │ ────────────────────────→ │ 激活API       │
│ ·算本机hwfp  │   {key, hwfp, nonce, ts}  │ ·O(1)预检     │
│ ·联网发key   │  （v2砍客户端sig·P1-3）    │ ·限流(IP+key) │
│ ·收到verify  │ ←──────────────────────── │ ·验key签名     │
│ ·通过→解锁    │   {ok, expire, bound_hwfp,│ ·key未绑定→首绑│
│ ·失败→冻结    │    server_sig}            │ ·验key未到期   │
└─────────────┘                          └──────────────┘
```

**核心原则（继承v2定稿+方向1.5裁决）：**
- 验证权威在服务器；本地EXE明文层无激活检查点（实测：无verify_license_key/已激活/YS2-/hwfp串）——激活门禁+核心算法在Cython .pyd+C++(solver_verify.exe)二进制层，逆向门槛=Cython二进制级（够挡普通场景，不承诺防国家级持续逆向）
- 机器指纹（hwfp）绑定在服务器侧核对 → 一个key只能激活它首次绑定的那台机器
- key内hwfp**留空占位**（v2·P1-1），首次激活由服务器写入绑定——keygen不预收集hwfp（零人工）
- 不预先收集hwfp → 首次运行自动生成+绑定（自动绑机）

## 二、激活协议（详细流程）

### 2.1 客户端（解限版EXE·hamilton_ui_v2接入）

**时机：** 启动激活门禁处 + 首次求解前（联网校验）

```
1. 计算本机 hwfp = hardware_fingerprint()
   （v2·P0-2：只用 CPU + 主板 + 硬盘序列号，SHA256前32位——去MAC化：
    Windows连接级随机MAC导致hwfp漂移（换网/蓝牙重连就变）→合法用户换网被拒。
    禁读连接MAC；若需网卡分量→读物理MAC（注册表HKLM...NetworkAddress/WMI物理网卡），不用连接级MAC）
   （v2.1·P1-C：hwfp分量=**CPU+主板**（选②"可替换分量最少"，硬盘序列号对换盘误伤大——
    换硬盘=激活被拒死锁；CPU+主板更换频率低且换主板本身=换机器，重绑可人工处理））
2. 读本地 license.key（若有）
3. 组装请求（v2·P1-3：砍客户端sig——Ed25519私钥藏EXE内可被逆向提取，
   签名只由服务器做（key身份签名）即可）：
     nonce = 16字节随机    os.urandom(16)
     ts    = Unix 时间戳ms
   载荷 = {key, hwfp, nonce, ts}
4. POST https://yunshao-ai.icu/api/v1/activate
5. 响应:
     {ok:true, expire:<ts>, bound_hwfp:<hwfp>, server_sig:<sig>}  → 解锁·写本地缓存
     {ok:false, code, msg}                                        → 冻结·提示
     HTTP 429（限流） → 指数退避重试（v2.1·P2-A：30s→2min→10min，上限3次，超限提示"激活请求过频，稍后重试"）
6. 断网/超时 → 用已激活缓存（v2·P1-2：冻结时间源=缓存内expire时间戳，本地时钟只参考）
   （v2.2·P1-F故障模式区分——可用性命门：
    · **网络不可达**（DNS失败/连接超时/TLS失败）→ **故障宽限**：缓存expire+7天可用（服务器故障≠用户违约，
      区别于验签失败的安全事件；备选：距最后成功验证<30天且服务器不可达→放行）
    · **验签失败/响应异常**（安全事件）→ 立即冻结+提示
    · 服务器故障公告页（yunshao-ai.icu/status）+知世一次性离线解锁码（应急发放））
```

**本地缓存（v2·P1-2·防离线绕过冻结）：**
- 缓存内容 = {key, bound_hwfp, expire, server_sig}（server_sig=服务器激活时用服务器私钥签名返回）
- 启动时验：①server_sig有效（服务器公钥验签）②bound_hwfp == 本机hwfp ③缓存完整性（篡改检测：签名覆盖全字段）
- **server_sig验签失败路径（v2.1·P1-B）：验签失败（私钥轮换/签名格式升级/缓存损坏）→视为无缓存→走联网激活；
  联网激活失败→冻结+提示"需网络激活"（不静默解锁，防降级攻击：攻击者损坏缓存迫使宽松路径）**
- **冻结时间源 = 缓存内 expire 时间戳**（服务器上次验证返回）——本地时钟只做参考（防改本地时钟延长冻结期）；本地时钟与expire偏差超过阈值（如>24h）→提示校准
- 断网+改时钟+复制缓存到另一台机器 → ①hwfp不匹配拒 ②复制时缓存签名仍在（篡改检测不触发）但hwfp匹配失败 → 冻结
- 离线宽限：expire内可离线用（缓存签名+hwfp匹配通过）；过期后冻结需重新联网

**防重放/防伪（v2修正）：**
- nonce随机16B + ts容差±30s · 服务器滑动窗口拒重放
- key必须由知世侧keygen签名（Ed25519验签·服务器做），任意客户端无法伪造合法key
- 客户端不持私钥（v2·P1-3）→无私钥提取风险

### 2.2 服务器（华为云·激活API）

```
POST /api/v1/activate  body={key, hwfp, nonce, ts}

0. O(1)预检（v2·P1-4：验签前零成本过滤——防验签DoS）：
   · key格式/长度/字符集（YS2-{tier}-{ts}-{hwfp占位}-{sig0} 结构正则）
   · tier ∈ ACTIVATION_TIERS
   · 限流（v2.1·P1-D修正：IP限流放宽到**60req/min**（只防脚本轰炸，NAT多机出口不误伤），
     **key级 10req/min 为主防线**（防单key枚举/重放）；超限429）
   · 激活API仅对分发清单IP段开放（v2.1：**白名单按机构网段CIDR**非单IP——哈工大教育网NAT出口）
1. 验 ts 容差±30s、nonce未重放（滑动窗口N=1000）
2. 解析 key = YS2-{tier}-{ts0}-{key_hwfp}-{sig0}
   · 验 key 的Ed25519签名（HAMILTON域公钥·身份验证）
   · 验 tier 有效 + 未到期（now < ts0 + tier_dur，防回调）
3. 绑机核对（v2·P1-1：key内hwfp留空占位→首次激活写入绑定）：
   · 查 key→hwfp 绑定记录（DB）
   · 若 key 未绑定 → 首绑保护（v2.1·P1-A：防EMPTY key先到先得劫持）：
       ①分发清单预登记（key→目标机构·首绑hwfp须在目标网段CIDR内）
       ②首绑窗口（签发后 N 天未首绑→key作废，N=30）
       ③首绑即通知知世确认（防劫持预警）
       （v2.2·P1-E：CIDR从硬门槛降**软信号**——首绑源IP不在CIDR→**不直接拒**，标记pending+通知知世人工确认；
        首绑通知（③）本身已覆盖劫持预警，CIDR仅作辅助信号，防校园网外（出差/回家/多校区/运营商切换）首次激活误伤）
     满足①②③ → 写入绑定 = 请求 hwfp（自动绑机，零人工）
   · 若 key 已绑定 → 验请求 hwfp == 绑定 hwfp（防移植）
4. 成功：返回 {ok, expire, bound_hwfp, server_sig}
   · server_sig = 服务器私钥对 {key, bound_hwfp, expire} 的Ed25519签名（客户端缓存验签用）
   · 重复请求同key不同hwfp → 拒绝（key被移植=防复用）

防线：
- key有效但已绑定别的hwfp → 拒（防多机复用）
- key过期 → 拒
- 伪造key（签名不符）→ 拒（O(1)预检后验签）
- 重放nonce → 拒
- 高频激活请求 → 限流429（IP 60req/min + key 10req/min）+ CIDR白名单（防验签DoS·P1-4/P1-D）
- EMPTY key窗口期劫持 → 预登记+首绑窗口+首绑通知（P1-A）
```

**服务器端代码：**
- Flask/轻量HTTP，仅路由.py + 逻辑编译（铁律12 Linux版：Cython→.so 或独立验证模块）
- 公钥存服务器受保护位置（HKDF(Ed25519(server_hwfp), salt||month) 体系可选）
- 入站只开443（华为云安全组已配），nginx反代，fail2ban
- 1.95.148.59 · yunshao-ai.icu（TLS已配，2026-10-27到期）

## 三、密钥签发（keygen_hamilton.py·知世侧）

- 档位：`1m`（1个月·2592000s·ACTIVATION_TIERS已有）
- 命令：`python keygen_hamilton.py 1m` → 签 `YS2-1m-{ts}-EMPTY-{sig}`（v2·P1-1：key内hwfp**留空占位EMPTY**，不预收集hwfp）
- **key内hwfp=EMPTY占位；首次激活时服务器把请求hwfp写入 key→hwfp 绑定记录（DB）**——
  keygen不需要hwfp（零人工·自动绑机），服务器按"key未绑定→首绑写入；已绑定→验等"（v2·P1-1明确单一模型，消除方案A/B内部矛盾）
- 100个key = 维护一个 key↔绑定记录 台账（服务器DB自动记，无需人工）
- **签名私钥：HAMILTON域 seed=SHA3-512(p||q||"YUNSHAO_HAMILTON_V1")[:32]，读goldbach_private.enc+口令（知世专用，绝不出包）**

**服务器签名（v2新增·缓存验签用）：** 服务器另有服务器域私钥（与keygen私钥分离），激活成功时对 {key, bound_hwfp, expire} 签名返回 server_sig（客户端缓存防篡改用）

## 四、防破解设计（v2修正·P0-1降级后表述）

> **v2·P0-1降级说明（知世03:26批方向1.5）：** 攻击手原P0-1"破解EXE=白破"前提=明文层有激活检查点可patch。实测（熵墟strings扫描）：样本EXE明文层**无**verify_license_key/已激活/YS2-/hwfp等检查点——激活门禁+核心算法在Cython .pyd+C++(solver_verify.exe)二进制层，逆向门槛=Cython二进制级（等同V1000）。据此**不写"破解EXE=白破"**，改写：激活防多机复用+防key伪造+逆向门槛够用（不承诺防国家级持续逆向）。

| 攻击场景 | 防线（v2） |
|---------|-----------|
| 提取密钥/算法 | 核心算法在 solver_verify.exe（C++二进制）+ 三.pyd，无源码；激活门禁+验签在Cython二进制层（逆向门槛=Cython二进制级，够挡普通场景） |
| 替换公钥伪造key | key验证在服务器（keygen签名验签），本地无权威公钥可替换 → 伪造key签名不符拒 |
| 一个key多机复用 | 服务器记录 key→hwfp 首次绑定（v2：key内EMPTY占位→首绑写入DB），异机再激活拒绝 |
| 改时钟延长期限 | key内ts + 服务器当前时间校验 + 防回调；v2：冻结时间源=缓存expire（服务器返回），本地时钟只参考 |
| 重放请求 | nonce滑动窗口 + ts容差 + 服务器验key签名 |
| 断网绕过 | v2：离线用缓存（hwfp匹配+server_sig验签通过）至expire，过期冻结需重新联网；复制缓存到他机→hwfp不匹配拒 |
| DoS来触发销毁 | 继承v2：冻结可恢复·永不自动销毁（防攻击者触发全灭）；v2新增：O(1)预检+限流+IP白名单（防验签DoS） |

## 六、决策链（v2追加）

- 决策1（v1）：B方案（服务器自动绑机激活）替代A（手动取指纹）。理由：知世03:16指示"要B"；B零人工+真防多机复用。可证伪：若服务器延迟/断网导致合法用户无法激活（误伤率>阈值）→需离线降级或饱和缓存。
- 决策2（v1）：key内绑hwfp + 服务器首绑记录。理由：防一个key多机复用。可证伪：若同一物理机重装系统hwfp变化→hwfp算法需含重装稳定分量。
- **决策3（v2·知世03:26批方向1.5）：保留现有加密（明文层无激活检查点实测，逆向门槛=Cython二进制级，够挡普通场景），不搞瘦客户端化（方向2）。理由：实测明文层无检查点=现有加密够强；方向2（持续联网+服务器承载算力+架构重写+配额卡）大工程换伪承诺不值。可证伪：若实测EXE明文层含激活检查点可一行patch→方向1.5不成立。**
- **决策4（v2）：P0-1降为P1。理由：明文层无检查点实测（strings扫描无verify_license_key/已激活/YS2-/hwfp）。可证伪：若有人不逆Cython直接patch→降级错。**
- **决策5（v2）：hwfp去MAC化（CPU+主板+硬盘序列号）。理由：Windows连接级随机MAC导致hwfp漂移（换网被拒）。可证伪：若某机器CPU+主板+硬盘序列号全不可读→hwfp无法生成（需降级方案）。**
- **决策6（v2）：key内hwfp留空占位EMPTY，服务器首绑写入。理由：消除keygen需hwfp（方案A手动）vs 自动绑机（B零人工）内部矛盾（P1-1）。可证伪：若key分发后首绑前被盗用（先到先得）→需分发清单预登记。**
- **决策7（v2）：冻结时间源=缓存expire（服务器签名返回），本地时钟只参考。理由：防断网+改时钟离线绕过冻结（P1-2）。可证伪：若缓存被整包复制+hwfp伪造→缓存防线失效。**
- **决策8（v2.1·P1-A）：EMPTY key首绑保护=分发清单预登记（key→目标机构CIDR）+首绑窗口（30天作废）+首绑通知知世。理由：防key截获先到先得劫持（100个key逐个被劫）。可证伪：若攻击者伪造分发清单→预登记失效。**
- **决策9（v2.1·P1-B）：server_sig验签失败→视为无缓存→联网激活；联网失败→冻结+提示"需网络激活"。理由：私钥轮换/格式升级/缓存损坏的降级路径必须定义（防降级攻击：损坏缓存迫使宽松路径）。可证伪：若验签失败路径被滥用为永久免验→漏洞。**
- **决策10（v2.1·P1-C）：hwfp分量=CPU+主板（选②可替换分量最少，弃硬盘序列号）。理由：换硬盘误伤大（死锁），CPU+主板更换=换机器本身可人工重绑。可证伪：若CPU+主板序列号在部分OEM机不可读→hwfp生成失败需降级。**
- **决策11（v2.1·P1-D）：IP限流放宽60req/min（NAT多机出口不误伤），key级10req/min为主防线，白名单按机构CIDR。理由：哈工大100台共享教育网NAT，1req/min=100分钟激活完。可证伪：若脚本轰炸借NAT多IP绕过key限流→key级限流需收紧。**
- **决策12（v2.1·P2-A）：429重试=指数退避（30s/2min/10min上限3次）+提示。P2-B：IP白名单=配置项，知世批改。**
- **决策13（v2.2·P1-E）：首绑CIDR降软信号（不在CIDR→pending+通知知世人工确认，不直接拒）。理由：首绑决定key生死，校园网外（出差/回家/多校区）首次激活被硬拒=误伤；首绑通知（P1-A③）已覆盖劫持预警，CIDR仅辅助。可证伪：若CIDR软信号导致劫持漏网（攻击者从CIDR内激活）→需回硬门槛。**
- **决策14（v2.2·P1-F）：故障模式区分——网络不可达→故障宽限（缓存expire+7天）；验签失败/响应异常→冻结；备选：距最后成功验证<30天且服务器不可达→放行。理由：服务器永久故障（域名挂/欠费/账号问题）若归冻结=全用户永久冻结=可用性命门，比激活漏洞更致命。可证伪：若故障宽限被滥用（主动断网拖延过期）→宽限窗口需收紧或加验证频率。**
