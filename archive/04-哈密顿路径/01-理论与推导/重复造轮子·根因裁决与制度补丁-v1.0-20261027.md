## §3 根因裁决（为什么会这样）

**不是"不知道现货存在"**——软件清单、Manifest、工具链 README 我都打开了。
**根因=任务触发时没执行"现货对照"这个动作**：你说"更新求解器"，我直接把"更新"理解为"写一个新求解器"，而不是"①查现货台账→②找出现货与需求的差距→③差距成立才写新代码"。**工具链 README 里其实写着这道工序**（"三查问：造轮子前强制①查原生方案图谱②查已验证工具链③查本机已装库。三查不过禁止造轮子；造轮子必须书面说明'现成工具做不到什么'"）——我读了没执行，说明**工序存在于文档≠工序被执行，必须有强制触发点**。

## §4 制度补丁：三查问前置化（并入文献先读铁律）

**触发时机改为一句话硬闸**：

> 凡任务涉及"做/更新/写"任何代码、工具、求解器、文档——动手前必须先输出**《现货对照表》**：该需求对应的在役现货清单（从软件清单+工具链+Manifest 查）＋每项现货与需求的差距＋"为什么现货不够用"一句话论证。**三查问答不上"现货为什么不够用"，禁止写第一行代码**；现货够用=直接调用现货交付。

已并入 AGENTS.md 文献先读铁律细则第 6 条（见文末登记）。对照本条：检讨件（哈密顿线）的"必读回执"管**读**，本补丁的"现货对照表"管**用**——读和用之间这道闸就是防重复造轮子的最后一道。
