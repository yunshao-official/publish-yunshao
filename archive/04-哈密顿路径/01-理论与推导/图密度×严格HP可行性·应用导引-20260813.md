## 一、核心结论（一句话）

**严格哈密顿路径（0断边+全覆盖+无重复）能否存在，由图的稠密度（容量）决定，不是算法问题。** 稀疏真实网络（平均度≤6）普遍数学不可能，用 walk（100%真边+允许重复）才是匹配真实形态的正解；稠密/规则图严格可行。

**规律：平均度≥10（或满足Dirac类稠密条件）→ 严格HP普遍可行；平均度≤6稀疏 → 普遍数学不可能。**

## 三、应用场景判断（知世关注的三个场景）

### 1. 刑侦关系链（人们之间的关系网络）→ 用 walk
- 真实人际关系 = 稀疏无标度（少数hub+大量低度节点）→ 严格HP经常不存在
- **不需要严格路径**：目标=一条路径覆盖所有嫌疑人/关键人物
- **walk 是正解**：100%真边+全覆盖+9.5s(10⁶)，hub重复=中间人多次经手（真实形态）
- walk 不是妥协，是匹配真实关系的形态

### 2. 芯片（布线/超大规模集成电路）→ 严格HP可行
- 芯片图 = 网格/超立方体/模块化 → 结构规则、容量充足
- Grid3D 10³ 实测严格PASS（0断边/5.8s）→ 芯片布线可走严格路径
- 注意：真实芯片布线有几何约束（不交叉/层间via），需在基础路径上叠加约束检查

### 3. 程序（调用图/依赖图）→ 多数可行，容量秒级判定
- 程序调用图/依赖图通常稠密或分层 → 多数严格HP可行
- 工具：容量检查（capacity_check.py）秒级预筛，容量不足直接标不可行
- 稀疏的（如死代码多）→ walk 兜底

## 四、决策流程（给使用者的判断树）

```
拿到一张图
  │
  ├─ 先跑容量检查（秒级）【20260826勘误：对任何图必须实跑，禁凭标签推断——P1-8按图执行条款】
  │    ├─ 容量不足 → 严格HP数学不可能 → 用 walk（100%真边+全覆盖）
  │    └─ 容量充足 → 跑严格求解器【勘误：flow满=必要条件预筛，非存在性保证；能否0断边取决于搜索】
  │         ├─ 0断边 → 严格PASS ✅
  │         └─ 有断边 → 修复循环 → 0断边 or 逼近下界
  └─ 平均度≥10 的图 → 直接严格求解（大概率可行）【勘误：经验规则，仍以实跑容量检查+求解验证为准】
```

## 五、体系意义

1. **容量定理=判断工具**：不是"算法好不好"，是"图允不允许"——先把图的宿命算清楚，再选工具
2. **walk=稀疏真实网络的普遍解**：100%真边+全覆盖，正是为 m=3 型真实网络量身打造
3. **严格=稠密/规则图的解**：芯片/网格/稠密网络用它
4. **七边理论嵌入**：完美边（最短路径边）在稠密图富集=严格解通道；全能边（多特性复合）在难图中是杠杆点（实测-90 vs -52修复力）
