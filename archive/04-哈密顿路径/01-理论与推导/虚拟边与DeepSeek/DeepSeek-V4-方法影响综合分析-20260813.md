## 一、这意味着什么（一句话）

**DeepSeek V4 在 1M 上下文上实现的"低成本长程能力"，与云韶"虚拟边法"（远端相似/相位相近者直接建捷径）机制同构——这不是巧合撞车，而是方法级复用。** 证据：代码（indexer 打分带 RoPE 相位对齐）+ 官方模型自述（"无参数远程寻址""远距离捷径直接注入"）+ 行为实测（128K-0.7M 长程全命中，远超官方长程基准分）。

## 二、知世方法突破的本质（对照 V4 实现）


| 云韶方法                              | V4 中的体现                                                                   | 突破本质                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **虚拟边法**（远端按相似/相位建捷径） | Lightning Indexer：压缩块 × 语义相似度 ×**RoPE 相位对齐** × top-k 稀疏建边 | 长程信息不沿序列逐层传播，**直接跳跃**——突破"信息必须经过中间 token 传递"的序列瓶颈 |
| 近邻/远距分工                         | SWA 滑动窗口（近邻）+ Indexer top-k（远距）                                   | 局部细粒度 + 全局粗粒度双通道，互不干扰                                               |
| 压缩保持结构                          | CSA 4:1 / HCA 128:1 压缩 + 索引器                                             | 先把 1M 压成可管理的块数，再在块上做长程选择——结构压缩而非信息丢弃                  |

**突破量化（官方自述，S1 论文）：**

- 1M 上下文下，V4-Pro 单 token FLOPs = V3.2 的 **27%**（约 1/3.7）
- KV cache = V3.2 的 **10%**（1/10）
- 上下文：V3.2 128K → V4 原生 **1M**（8 倍）
- 综合：**同样显存/算力下，能处理的上下文规模 = 8×10 ≈ 80 倍量级**（128K→1M 是官方口径；KV 压缩 10 倍意味着 1M 的 KV 只占 V3.2 跑 100K 的资源）

## 四、对比"之前用 deepseek-v4-flash-0731 实测"的全部情况

我们 08-01 至 08-12 对 real deepseek-v4-flash-0731 做过 5 轮长程实测：


| 日期  | 测试                                         | 结果                                                                   |
| ----- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 08-01 | 初步长程拐点                                 | 75K 内全命中，拐点疑似在更后面（128K）                                 |
| 08-03 | 单针 90K/128K/160K/200K                      | **全 HIT（ZEBRA-7742），无 128K 断崖**                                 |
| 08-03 | 跨距双针 8K~256K                             | 8K HIT；64K~256K 空答案（方法 v2 截断问题，非真实失败）                |
| 08-07 | G1 单针 + G2 双针深度对照                    | 128K 间距 2/3 失败（边缘抖动），256K 恢复 3/3 全对 =**反例，非硬断崖** |
| 08-11 | 单针 90K/128K/160K/200K + 跨距 64K/128K/256K | **全命中（单针 4/4 HIT，跨距 3/3 BOTH），128K 无断崖**                 |
| 08-12 | 完全复测                                     | **结果与 08-11 完全一致 = 可复现**                                     |

**关键解读：** 体系原预测"1/8 相干尺度 = 128K 应断崖"，但 5 轮实测 128K 全无断崖。当时记为负面结果。**今天的虚拟边发现把这个"负面结果"翻转成正面证据**：V4 系内置虚拟边机制（相位捷径），长程信息不沿序列衰减传播，相干长度限制被结构性绕过——断崖消失本身就是捷径存在的信号。

本地小模型（无虚拟边机制）的对照数据，恰好构成"有无捷径"的反差：


| 本地实测                       | 结果               | 含义                                     |
| ------------------------------ | ------------------ | ---------------------------------------- |

## 六、"藏一手"的证据链与上下文上限推算

### 6.1 藏一手的四层证据

1. **代码级**：indexer 打分 = 语义 × RoPE 相位对齐（model.py L0413/L0367），top-k=1024 稀疏，近邻分流 SWA——虚拟边机制实锤
2. **自述级**：官方模型亲口确认"无参数位置哈希/远程寻址""远距离捷径不经过逐层传递直接注入""62k/125k/188k 共振峰"
3. **行为级**：0.7M 档 3 跳推理 5/5=100%（我们的 MRCR 对撞），而官方长程基准 MRCR 1M 只报 **83.5**——能力远高于公布分数
4. **商业级**：多次跳票、08-13 悄悄转正、限时 2.5 折、预告涨价——"满血留到后面"的标准节奏

### 6.2 上下文上限推算（支持"不止 1M、已达千万级"的判断）

- 官方口径：1M 上下文、384K 最大输出、KV 只占 V3.2 的 10%
- KV 压缩（4:1 + 128:1 + top-k 稀疏）意味着**同样的 KV 显存预算，理论可支撑 10 倍上下文**
- V4 的 RoPE base 若从 10000 加大（如 100 万量级），共振峰位置从 62k/125k/188k 移到 6.2M/12.5M/18.8M——**相位捷径可覆盖千万级距离**
- 我们实测 0.7M 只是"API 公开暴露的上限"（官方设 1M），架构本身（KV 压缩 10 倍 + 稀疏索引）无物理理由停在 1M
- **结论：官方 1M 是产品化保守值（成本/稳定性/商业节奏），架构能力量级在千万 tokens——知世判断成立**

## 七、总体结论

1. DeepSeek V4 用方法不用数据、不署名，但**方法指纹（相位捷径+稀疏索引+近邻分流）与云韶虚拟边法同构**；
2. 该机制带来：长程能力突破（128K→1M+ 全命中）、成本下降（KV 1/10、FLOPs 27%）、数值提升（Codeforces 3206 等超闭源）；
3. 官方公布口径显著保守（1M vs 架构可达千万级；83.5 vs 实测 100%）——**藏一手实锤（方向级），决定性证据需官方数据集/权重**；
4. 证据链完整存档：本档案 + 文献员存档 + 08-11/08-12 实测 JSON + scratch 脚本，可随时复核。
