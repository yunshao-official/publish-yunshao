## 四、工程设计书（核心）

### 4.1 五层文档架构

```
L0 常数与结论正本  constants.yaml（唯一可编辑源，机器可读）
    字段：name / value / formula / unit / status / source_doc / effective_date / version
    分层口径沿用 0913 内洽版：Λ_cry/Λ_pat/Λ_dis 分域；层1 Θ(8) 写入相空间 vs 层2 Θ(48) 材料本体分记
L1 总索引          INDEX.md（每文件一行：路径|日期|一句话|状态|依赖常数版本）——由脚本再生
L2 摘要头          每文件 YAML front matter（≤300字）：title/date/version/status/constants/deps/summary
L3 正文            压缩军规写作（4.4）
L4 归档            被取代版本移入归档目录（保留可追溯，禁止删除——现"归档-旧常数体系"模式）
```

铁律三条：**L0 只有一份**；**L1/L2 是生成物可随时再生**；**L3 不许复述 L0 内容，只写锚点引用**（如 `[Θ(N)表:v1.3]`）——"引用代替复述"是压缩的最大杠杆。

### 4.2 更新流水线（突破触发七步，接在学术工程一体化流程第 8 件"登记"之后作为其超集）

1. **登记**：台账批次 + front matter 摘要头（既有惯例）；
2. **影响面扫描**：`scan_deps.py` 反查 constants_version/deps → 自动生成"待更新下游清单"（K-4 惯例机械化）；
3. **重算**：`gen_tables.py` 从 L0 再生全部派生表（Θ(N) 表、场量值表），文档只存"脚本+版本"引用；
4. **降级标注**：旧值文档头部自动追加"⚠️ 已过时 → 见 vX.Y（日期）"，不删原文；
5. **索引再生**：`build_index.py` 重建 L1；
6. **双版本发布**：人话版导读（知世/人类读者）+ 启动包更新（AI 读者）；
7. **登记五处**：台账批次/审查包与交付包双副本/工作区索引/daily/MEMORY（既有惯例原样）。

**裁决轨**（与流水线并行）：知世每条裁决入 `memory/adr/registry.json`（复用优化草案 v3 已定格式，扩字段：`type: constant/method/scope`, `affects[]`）——裁决不再散落对话，AI 下次开机可查。

### 4.3 AI 可读性规范

- **启动包**（任何新 AI 会话的第一口粮，≤8k tokens）= L1 总索引 + L0 常数正本 + P0 问题清单 + 本机制。落盘为 `H:\理论存档\00-其他\启动包-最新.md`（脚本再生，永不过期——文件名不带日期，内容带版本）；
- **状态标签强制枚举**（写进 front matter，非法值=lint FAIL）：`定稿 / 内部版 / 对外版 / 复算一致 / 体系内部定义·未验证 / 理论参照·非实测 / 已判负 / 已封存 / 已作废 / 草案`；
- docx/pdf/xlsx 一律要求同目录存在 `.md` 提取件（正本 docx 事故的直接整改；《天工开物计划·全文提取》两份 txt 0916 已开了先例，统一改 .md）。

### 4.4 压缩军规（写作纪律，违者 lint 报警）

1. 新文件正文 ≤5000 字；超限必须拆分，或文首附 ≤300 字压缩版；
2. 禁三样：不复述背景、不复述体系定义（用锚点）、不写无信息增量的总结段；
3. 台账卷宗制：每 20 批次出一份卷宗摘要，老批次正文可只读摘要；
4. 月度回顾代记忆：当月产出以月度索引为准，过期 daily 移 L4 归档；
5. 一事一文件：版本演进用"新文件+旧文件头标注被取代"，不在原文件内无限追加（台账批次制除外，它是 append-only 正本）。

### 4.5 人话层（双读者保障）

- 每份交付带人话版导读（既有惯例保持不变）；
- 月度回顾 = 人类读者的唯一月度入口（本次已建立，以后每次触发产出一期）；
- 状态广播板（OpenClaw memory 下已在跑）继续承担跨 agent 通告。

### 4.6 工具清单（执行器层，主流软件工程；全部纯本地 Python，禁止任何 API 调用——执行通道铁律）

| 工具 | 功能 | 验收判据（冻结） |
|---|---|---|
| `lint_docs.py` | 扫描 front matter 缺失/正文字数超标/状态标签非法/无锚点复述 | 任一新文件无摘要头 = FAIL 清单非空 |
| `scan_deps.py` | 按 constants_version + deps 反查全部下游文件 | 改 L0 后必出非空清单；α 改值场景清单≥正本层 10-15 份（对齐 0906 普查先例） |
| `gen_tables.py` | 从 L0 再生 Θ(N) 表/场量表/通道参数表 | 再生输出与现行 ys_*.json 逐值一致（复算一致） |
| `build_index.py` | 从 front matter 再生 L1 总索引+启动包 | 索引行数 = 主目录文件数（备份目录除外） |
| 月度回顾 | 子代理分域精读→总索引+附录（人工触发） | 覆盖主目录全部 md；遗留问题并入总账 |

**BOM（成本≈零）**：纯 stdlib（re/os/json/hashlib）+ 已有 python-docx；无需购件，运行于现有 Windows 工作机。工期：四脚本合计 2-3 个工作日（子代理夜间免费窗口执行）。

## 七、人话版导读

把全库想象成一间实验室：
1. **constants.yaml 是唯一的账本正本**——所有常数只在这里改，别处都是抄账；抄的账必须注明"抄的哪一版"（就像引用文献带版本号）。
2. **改账本时，一个脚本自动列出所有抄过账的文件**——这就是"影响面扫描"，α 常数当年靠人翻 153 个文件的事，以后是秒级。
3. **每个文件开头贴一张 300 字小抄**（摘要头）——AI 和人先看小抄，决定要不要读全文；AI 每次开工只带"地图+账本+待办清单"（≤8k tokens 的启动包），再也不用把 122KB 的台账整个吞下去。
4. **每月大盘点一次**——就是这次交付的《月度回顾与总索引》：三个 AI 分头精读、汇总成一份索引+一份遗留问题总账。您喊一声"月度回顾"才做，绝不自动巡检。
5. **写作军规**：新文件不超 5000 字、开头必有小抄、体系定义只引用不复述——从源头治"废话多、上下文不够用"。
6. **您的裁决进 ADR 登记册**——每条裁决一行机器可读记录，AI 永远能查到"哪天为什么改了哪个数"，不会再出现"两份同日文件打架"。
