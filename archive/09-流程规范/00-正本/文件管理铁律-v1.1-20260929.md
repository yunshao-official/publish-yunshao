## 一、写入门禁（防新乱）

1. **落位**：新文件必须落入对应编号目录（00-其他 / 01-数学 / 02-物理 / 03-高维材料工程 / 04-哈密顿路径 / 05-天体物理 / 06-云韶工程控制论 / 07-计算 / 08-能源工程 / 09-流程规范 / 10-治理与哲学 / 11-军事应用 / 12-YUNSHAO软件工程（自编号） / 13-密码学 / 14-航天工程 / 15-计算与信息技术 / 16-生命与营养工程 / 17-物理预测）。**理论存档根目录禁止新增散文件**（现存散文件由 M 任务统一归位，见第七节）；
2. **命名**：`主题·类型-版本-YYYYMMDD.md`；版本演进 = 新文件 + 旧文件头部标注"⚠️ 已被 X 取代（日期）"，**禁止覆盖他人/既有文件，禁止原地改历史档**（台账 append-only 除外）；
3. **摘要头**：每个新 md 必须带 ≤300 字摘要头（标题/日期/版本/状态标签/依赖常数版本/一句话摘要）；状态标签枚举以 `constants.yaml meta.status_labels` 为准（定稿/内部版/对外版/复算一致/体系内部定义·未验证/理论参照·非实测/已判负/已封存/已作废/草案）；
4. **锚点引用**：常数与体系公式只许锚点引用 `[constants:vX]`，**禁止在正文复述数值**——数值改版只动 constants.yaml 一处，复述即制造未来的不一致；
5. **可读性**：docx/pdf/xlsx 落盘必须同目录配 .md 提取件（AI 不可读=会漏读，天工开物漏读 2/3 事故在案）；
6. **备份目录只读**：_归档-* / backup_* / 云韶备份 / 归档-旧常数体系 一律禁止写入、禁止当工作区、禁止引用其内容为现行口径（引用须走勘误块）。

## 一甲、变更分级与影响面（v1.1 新增·对标阿波罗 CCB）

> 立法缘由：正本重写律（单文件自包含）对文档很好，但设计/判据类变更缺 delta 可追溯——多会话并行时，一处改动牵动哪些下游、该谁批，此前无制度承载。对标阿波罗 1967 年后确立的变更控制（CCB/ECR/ECN、Class I/II 分级）轻量化引入，**不改变重写律本身**。

7甲. **【修改记录】表强制两列**：凡承载设计/判据/流程/口径的正本文件，其尾部【修改记录】表（或变更表）必须含**影响面**与**变更级**两列：
   - **影响面** → 本次变更牵动的下游文件/条目清单（路径或条目号；"无下游"须写明"零下游已核"）；
   - **变更级** → Ⅰ类 / Ⅱ类（定义见 7乙）；
7乙. **变更分级**：
   - **Ⅰ类变更** → 改**判据文本**（冻结后的预注册判据）、**常数引用口径**、**正本切换**、**红线/影子状态**、**对外承诺**——须知世批准后方可生效（例外：知世原话/裁决本身就是批准来源，登记即可）；执行层勘误（笔误/编号/路径级）不算Ⅰ类；
   - **Ⅱ类变更** → 局部勘误、格式、补充说明、不触及判据与口径的增补——执行侧自决，记录在案即可（先斩后奏+单内可否决兜底）；
7丙. **变更三步**（Ⅰ类必走，Ⅱ类可省略为记录）：①变更申请（写清改什么/为什么/影响面）→②影响分析（下游逐条列名，标"需同步修订"或"不受影响"）→③变更记录（新正本修改记录表内留痕）。三步全部落在新正本的修改记录表内，**不另开变更单文件**（单文件自包含律优先）；
7丁. **升版前核查**（既有惯例成文）：升版前核查目标版本号与当日日期号是否已被并行会话占用（裁决单撞版事故 v1.37 先例）。

## 二、改动纪律（防搞乱）

8. **三不动**：不移动、不重命名、不删除既有文件——除非知世明示，或属 M 任务执行且完成第十节索引同步；
9. 移动/重命名后：旧路径必须在索引与广播中注明去向；正本切换必须旧文件头注"已切换→新正本路径"；
10. **批次号先读后占**：台账批次号先读台账末尾再占；并行作业先查有无会话在改同一文件（一体化流程既有纪律）；
11. **诚实账本**：判负/作废/封存文件不删除，头部标注后移 L4 归档目录——历史全保留可追溯。

## 三、索引系统（双系统职责）

12. **ZCode 侧**：`C:\Users\Administrator\.zcode\workspace\default\索引.md`（会话交付索引）+ `C:\Users\Administrator\.zcode\memory\`（MEMORY.md 稳定事实 / daily\YYYY-MM-DD.md 过程）；
13. **OpenClaw 侧**：`H:\OpenClaw\workspace\memory\文档索引-INDEX.md`（交付指针登记）+ `memory\状态广播板.md`（实时广播）+ `memory\adr\registry.json`（裁决登记册）；
14. 索引是地图不是仓库：每行=路径+日期+一句话+状态；索引与实体冲突时**以文件本体为准**并立即修复索引。

## 四、广播制度（知世 2026-09-16 令核心）

15. 凡发生下列任一变动，完成改动后**必须**在 `H:\OpenClaw\workspace\memory\状态广播板.md` 追加一条广播（格式：`- 日期 时间 [agent/事项] 做了什么·影响哪些路径·旧引用如何兼容`）：
    - 目录结构变动 / 文件移动或重命名
    - 正本切换（新正本生效、旧正本废止）
    - 常数改值（constants.yaml 版本变更）
    - 大批量补丁（≥5 文件的批量修订）
    - **Ⅰ类变更生效（v1.1 新增）**
16. 广播同时更新两级索引（第十二、十三条所列）；**只改文件不广播 = 搞乱**，视同违反本铁律；
17. 广播范本见第九节。

## 五、AI 入口（后来的 agent 必读）

## 十、术语字典（v1.1 新增·v1.0 原文无字典，按总纲元规则一补齐）

| 术语 | 人话解释 |
|---|---|
| 正本 | 一个条目唯一现行的权威版本文件；旧版保留归档不再维护 |
| 单文件自包含 | 修订=重写完整新文件；读者只读一个文件即得全貌（总纲元规则二） |
| 三不动 | 不移动/不重命名/不删除既有文件（除非知世明示或 M 任务+索引同步） |
| 五处登记 | 工作区索引/文档索引-INDEX/OpenClaw 交付包/daily/MEMORY（或 auto-memory） |
| 状态广播板 | H:\OpenClaw\workspace\memory\状态广播板.md——跨 agent 广播目录结构/正本切换/常数改值的板 |
| Ⅰ类变更 | 改判据文本/常数口径/正本切换/红线影子状态/对外承诺——须知世批准 |
| Ⅱ类变更 | 局部勘误/格式/不触判据口径的增补——执行侧自决+记录在案 |
| 影响面 | 一次变更牵动的下游文件/条目清单——修改记录表强制列（v1.1） |
| CCB/ECR/ECN | 变更控制委员会/变更申请/变更通知——阿波罗确立的变更三件（本铁律轻量化为"变更三步"，不另开文件） |
| append-only | 只增不改——台账类文件按时间追加、禁止回改历史行 |
| M 任务 | 存量治理任务（M1-M3），知识管理机制 v1.0 定义 |
| 受控文件 | 编号+Rev+签署+分发受管理的文件（《工程文件转化规范》v1.1 同词） |
