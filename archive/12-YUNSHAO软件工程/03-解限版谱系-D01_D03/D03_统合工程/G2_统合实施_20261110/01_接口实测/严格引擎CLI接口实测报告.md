## 二、接口事实（A1 侦察＋串表＋源码三方核对）

1. **真实 CLI**：`strict_hp N [seed] [--m m | --load-graph file] [--budget S] [--starts K] [--sweep S] [--dump prefix] [--match-only] [--from-walk f] [--allround f] [--lns-kmin/kmax/every/bthr …] [--rr-thr] [--opt3cap] [--neutral] [--no-graph-dump] [--dump-bin] [--gen-dump-only] [--selftest]`。usage 行只列前六个旗标，**--m/--load-graph 不在 usage 里但实测有效**（串表 HIT＋17 例实跑）。
2. **缺省值**（源码 L2396-2400，与实测一致）：seed=42、starts=3、budget=600、m=3。
3. **无 --help 保护**：首参一律 atoi；`--help`/`-h`/`--version`/`--bogus` 全部按 N=0 生成空图→访问违例崩溃（exit 3221225477=0xC0000005）。无参数时 exit 1 并打 usage（唯一干净退出）。
4. **无旧 CLI**：`--ba`/`--verbose` 串表 MISS，实测探针崩溃——**二进制不含现行 strict_hp.cpp 源码里的 v0.3 兼容层**（legacy_main/--ba/V=行）。源码 mtime 08-18 16:58 晚于二进制 tar 内 mtime 08-15 03:29：源码比二进制新，新 CLI 部分两者一致，兼容层是源码后加的。01 件"疑似对应源码"表述据此收紧为"新 CLI 段对应、整体晚于二进制"。
5. **边表格式**（load_edges，源码 L1969-1999＋实测）：`#` 注释可跳过；首个非注释行 `N E`；其后每行 `u v`；无向（双向挂边）；**CLI 的 N 参数被文件头 N 覆盖**（a6_n_mismatch 实测：CLI 传 999、文件 N=20，按 20 解）。
6. **授权**：YS_AUTH_TOKEN 串表 MISS；注入与不注入行为逐字一致（a7 对照 a2_ba_n20_s42）——**引擎不读令牌，纯计算件**；授权门在 GUI 层，与引擎无关。GUI 正源 L1612 的注入对本引擎是空操作。

## 三、能力读数（A2/A3，全部独立裁判复核）

### 3.1 BA 生成模式（--m 10 --budget 60 --dump out）

- N=20/50/100/500 × seed=42/1/2/3 共 16 例：**16/16 exit 0、strict=YES、裁判 PASS**；墙钟 0.029–0.048s/例（引擎自报 time=0.0s，repair_rounds=0，构造端直出）。
- BA 边数公式 E=mN−m(m+1)/2：**16/16 吻合**（对引擎自 dump 的图文件数边）。
- 补测 N=1000 seed=42：exit 0、strict=YES、裁判 PASS（999/999 真边）、E=9945 吻合、0.033s。
- 注意：N=1000 例 stderr 出现 `[STAGE3] ERROR: L=1000 missing=1000` 字样而终解合法——**中间阶段日志的 ERROR 字样不作失败判据**（见 §四缺陷⑥）。

### 3.2 边表导入模式（--load-graph --budget 60 --dump out）

- Cycle-20：裁判 PASS（0.03s）。
- Path-20：裁判 PASS（repair_rounds=1，0.04s）。
- **两三角一桥（6 点，有解）**：裁判 PASS（repair_rounds=1821，0.1s）——引擎不误判有解图，02 件附录甲#1 反例在引擎侧也成立。
- **星形 K1,5（度1叶5>2，结构无解）**：烧满 60s 预算、225,022 轮修复、exit 0、strict=NO、breaks=3，**仍写出 out_path.txt（非法路径）**；裁判 FAIL（首个非法步 k=0，4→5 无边）——正确拦截。补测 budget=1 同图：1.04s 烧满、同样 exit 0＋strict=NO＋非法路径文件，裁判 FAIL。
- 不连通图（5 点 2 边＋孤立点）：**崩溃** 0xC0000005（STAGE1 Dinic 匹配后）。
- 空文件：**崩溃** 0xC0000005（N/E 未初始化，读入垃圾值 N=32763）。

## 四、六处接口缺陷（适配层必须兜住，逐条有存证）

1. **非数字首参崩溃**（--help 等，0xC0000005）→ 适配器参数全验证后才发射；帮助文本由壳自带，不问引擎。
2. **无输入验证，四类崩溃**：空文件、不连通图、m=0、N≤2（0xC0000005 或 0xC0000409=3221226356）→ 适配层前置输入闸（空/断连/N<3/m<1 一律不喂引擎，走 L4 预检或 ERROR 明示）。
3. **无解图烧满预算＋写非法路径＋exit=0** → 成功判定只认「strict=YES ∧ 裁判 PASS」；**绝不以退出码或路径文件存在判成功**；超时语义=exit 0＋strict=NO（不是非零码）。
4. **不带 --dump 则路径序列无处可取**（a5_nodump 实测零落盘，stdout 只有汇总数字）→ 适配器恒带 `--dump`；路径文件每行一个节点；`_best_path.txt` 是修复中间产物，**只取 `_path.txt` 终稿**。
5. **无结构预检**（星形数学无解仍烧 60s/22.5万轮）→ 统合版 L4 保守预检必须在引擎之前（02 件设计已有，本实测实证其必要；桥块树判据现货在分图而治 v2.5 现版）。
6. **中间 stderr 可出现 ERROR 字样而终解合法**（N=1000 例）→ 日志翻译只作进度展示，失败判定只认终态 RESULT/VERIFY＋裁判。

## 五、输出协议事实（G2-B 接线依据）

- stdout 两行终态：`RESULT N=%d starts=%d L=%zu unique=%d dup=%d breaks=%d best=%d repair_rounds=%d time=%.1fs`；`VERIFY strict=YES/NO expansion=%.6f (0断边+全覆盖+无重复)`。与 GUI 正源 L1630-1648 解析式逐字吻合。
- `--dump prefix` 落盘三件：`{prefix}_graph.txt`（求解前写，N E 头＋边表，可作裁判用图）、`{prefix}_path.txt`（终稿路径，每行一个节点，失败也写）、`{prefix}_best_path.txt`（中间最优，可能出现）。
- 引擎不写报告文件（GUI 正源 L1645 注释属实，实测吻合）；报告由壳自建（`# version: v0.3-strict-engine` 协议冻结不变）。
- 退出码实测集：0（正常/超时/无解均 0）、1（无参数 usage）、2（文件打不开）、0xC0000005/0xC0000409（崩溃）。**退出码语义不完备，不可作判定主据。**

## 六、对 G2-B 的直接含义

1. GUI 正源 L1276/L1296 调用式（`N seed --load-graph file --budget 3600` / `N seed --m m --budget 3600`）与本二进制兼容，可原样继承；但须补 `--dump` 才拿得到路径（正源现式未带 --dump，其 strict Tab 只呈现汇总数字不导出路径序列——统合版按冻结输出协议补齐三件套导出时，路径来源就是 --dump）。
2. 子进程宿主（02 件 D⑥）必要性实证：本引擎四类崩溃面，进程内调用会带走 GUI。
3. 引擎无授权依赖 → 授权链复验（G2-D）只涉 GUI/auth 层，不涉本引擎。
4. 本引擎只找任意严格 HP 不优化成本、不做无解证书——四态中 INFEASIBLE_CERTIFIED 一律由 L4/SAT 出，不由本引擎出。
