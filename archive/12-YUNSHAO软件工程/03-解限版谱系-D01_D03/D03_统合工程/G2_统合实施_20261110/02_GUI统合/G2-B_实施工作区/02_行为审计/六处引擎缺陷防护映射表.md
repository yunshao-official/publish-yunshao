## 缺陷① 非数字首参直接崩溃（0xC0000005）

- **复现存证**：`a1_bogus.json`、`a1_h.json`、`a1_help.json`、`a1_version.json`（首参非数字→访问违例崩溃）；`a1_noargs.json`（无参→exit 1 usage，唯一正常拒绝态）。
- **防护模块**：`app/engine/strict_adapter.py`（参数全验证）＋`app/ui/strict_tab.py`（输入框第一道整数校验，v0.3 L1281–1289 已有，保留并加强）。
- **防护措施**：发射前校验 N 存在/整数/范围（N≥3，引擎 N≤2 崩溃见缺陷②）、seed 整数、m 整数且 ≥1、budget 正数、无空串/非数字/逻辑矛盾；任何一项不过→不发进程，返回 ERROR 并明示原因。帮助文本由壳自带，**绝不向引擎传 --help/-h 等非数字首参**。
- **必测用例**（任务书清单）：空输入、字母、小数、负数、极大数字、混合字符、缺失参数——各至少 1 例。
- **通过标准**：全部非法输入在 GUI/适配器层被拒；引擎进程零启动（进程计数断言）；零崩溃。

## 缺陷② 空文件/断连图等坏输入不检查直接崩溃

- **复现存证**：`a3_load_empty/`、`a3_load_disconnected/`（崩溃）；`a6_m0/`、`a6_n1/`、`a6_n2/`（0xC0000005 或 0xC0000409=3221226356）；`a6_missing_file/`（exit 2）；`a6_n_mismatch/`（头行 N 覆盖 CLI N 的语义陷阱）。
- **防护模块**：`app/graph/normalize.py`（输入闸＋标准化）＋`app/graph/precheck.py`（L4 结构预检）。
- **防护措施**：调用引擎前十项检查——文件存在/可读/非空/节点数有效/边格式合法/无非法编号/无自环/重复边去重登记/无越界边/连通性。图语义按 G2-A 实测：`#` 注释＋首非注释行 `N E`＋`u v` 无向边；头行 N 为准（CLI N 与头行不一致时以头行校验并明示）。空/断连/N<3/m<1 一律不喂引擎：空图/格式坏→ERROR；数学必要条件不满足→INFEASIBLE_CERTIFIED（仅证书，见缺陷⑤）。
- **必测用例**：空图、空文件、单节点图、两个互不相连分量、星形图、两三角形一座桥、含非法节点编号、含重复边、格式错误。
- **通过标准**：坏输入引擎启动前拦截；合法输入不过度拒绝；**两三角形一座桥回归锚必须继续过**（G2-A `a3_load_two_tri_bridge/` 裁判 PASS，预检不得误杀）。

## 缺陷③ 无解图烧光预算＋写非法路径＋exit=0

- **复现存证**：`a3_load_star_k15/`（星形 K1,15 数学无解，烧满 60s，写出非法路径文件，exit=0）；`a6_budget1/`、`a6b_forced_timeout/`（超时语义＝exit 0＋strict=NO，不是非零码）。
- **防护模块**：`app/engine/strict_adapter.py`（四条件合取判定＋唯一任务目录）＋`app/validation/strict_validator.py`（独立裁判）＋`app/engine/eng_host.py`（硬超时与进程管理）。
- **防护措施**：**SOLVED 当且仅当四条件同时成立**——(a) VERIFY 行结构化解析得 strict=YES；(b) RESULT 行完整解析；(c) 本任务 `_path.txt` 可读且格式合法；(d) 独立裁判重读输入图验证：路径长度=N、节点无重复、全覆盖、步步真边。任一不过→按四态映射处理（引擎自报成功但裁判失败→ERROR 并留存引擎输出/失败路径/失败边；预算耗尽→UNSOLVED）。**退出码与文件存在永不作成功判据**。每任务唯一临时目录（UUID/时间戳），输出文件不复用、不残留误认；`_best_path.txt` 中间产物永不读取。
- **必测用例**：已知有解图、已知无解图、超时图、伪造/残留路径文件污染、模拟 strict=YES 但路径非法、exit=0 但无合法路径。
- **通过标准**：任何不合法路径无法进入 SOLVED；超时→UNSOLVED 绝不→INFEASIBLE_CERTIFIED；污染测试中旧文件不被误认。

## 缺陷④ 不加 --dump 拿不到路径

- **复现存证**：`a5_nodump/`（不带 --dump：零路径落盘，stdout 只有汇总数字）。
- **防护模块**：`app/engine/strict_adapter.py`（CLI 构造）。
- **防护措施**：每次调用恒带 `--dump {task_dir}/out`（G2-A 实测参数，不依赖默认行为）；只取 `{prefix}_path.txt` 终稿（每行一个节点）；`{prefix}_graph.txt` 供裁判与导出；`{prefix}_best_path.txt` 禁用。发射后检查：参数已传入、文件已生成、属于当前任务目录、可读、格式合法、节点齐全。v0.3 正源 L1319–1321 的占位尾协议（`__ba_placeholder__`＋输出路径）不在实测 CLI 中，适配器弃用，改干净 CLI（N1）。
- **必测用例**：一次正常导出、连续两次不同任务导出、前次成功后次失败、路径文件读取异常。
- **通过标准**：每任务准确关联自己的输出文件；失败任务不继承前次文件。

## 缺陷⑤ 无预检，星形等明显无解图白烧预算

- **复现存证**：`a3_load_star_k15/`（星形无解仍烧 60s/约 22.5 万轮修复）。
- **防护模块**：`app/graph/precheck.py`（L4 保守预检，02 架构正本设计；桥块树判据现货在分图而治 v2.5 现版，复用须对照验证）。
- **防护措施**：引擎调用前只查**已证明的必要条件**，四类证书：EMPTY（空图）、DISCONNECTED（不连通）、DEG1_GT2（度1叶子>2）、BRIDGE_TREE_NOT_TRACEABLE（桥缩块树不可迹，必要条件违反）。命中→INFEASIBLE_CERTIFIED＋证书内容落报告；不命中→放行。**不得把经验规律写成数学证书**；两三角形一座桥（桥缩块后仍可迹）必须放行。预检保守性优先：宁可放行烧预算，不可误杀合法图。
- **必测用例**：星形图、不连通图、三个以上叶节点、两三角形一座桥、普通连通图、随机稠密图。
- **通过标准**：明显无解图引擎启动前被正确处理（证书齐全）；合法图零误拒；两三角一桥锚继续过。

## 缺陷⑥ 日志中途 ERROR 字样与终态无关

- **复现存证**：`a2b_ba_n1000_s42/`（stderr 出现 `[STAGE3] ERROR: L=1000 missing=1000` 而终解合法，裁判 PASS；G2-A 报告 §3.1 L35 明示）。
- **防护模块**：`app/engine/eng_host.py`（分流留存）＋`app/engine/strict_adapter.py`（终态判定）＋`app/logging/event_log.py`（日志只作进度展示）。
- **防护措施**：分别保存 stdout 文件、stderr 文件、退出码、RESULT 行、VERIFY 行、路径文件、独立裁判结果（七件独立留存）。最终状态只由结构化 RESULT/VERIFY＋裁判决定；**禁止 `if "ERROR" in stdout: fail()` 式判定**，也禁止"无 ERROR 即成功"。stderr 翻译只进进度条/日志窗，不进判定链。解析容错：缺字段/重复字段/非法数字/格式错/编码异常/不完整输出→明确报 ERROR，不猜测。
- **必测用例**：中途 ERROR 最终合法（用 N=1000 复现例）、中途无 ERROR 最终非法、有 RESULT 无 VERIFY、有 VERIFY 无路径文件、输出格式不完整、进程异常退出。
- **通过标准**：日志文字不再是单独的成功/失败判据；七件留存齐全可回溯。

## 四态映射总表（防护的统一出口）

| 情形 | 状态 | 禁止 |
|---|---|---|
| 四条件合取全过（strict=YES∧RESULT∧path∧裁判PASS） | SOLVED | 引擎自报成功直接→SOLVED |
| 预算耗尽/超时/strict=NO 且无证书 | UNSOLVED | 超时→INFEASIBLE_CERTIFIED |
| L4 必要条件证书命中（或 BA m=3 定理/CP-SAT INFEASIBLE，本引擎不出此类） | INFEASIBLE_CERTIFIED | 无证书武断判无解 |
| 输入/进程/文件/解析/裁判基础设施异常；自报成功但裁判失败 | ERROR | ERROR→UNSOLVED 包装 |
