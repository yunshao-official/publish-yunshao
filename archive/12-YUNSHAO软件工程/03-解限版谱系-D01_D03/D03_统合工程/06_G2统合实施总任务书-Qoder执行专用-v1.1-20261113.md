# 第一部分：你的角色、任务和最高优先级

## 1.1 你的角色

你不是一个只负责修改 Python 文件的普通代码助手。

你是本项目的：

1. 软件资产审计工程师；
2. GUI 逆向工程师；
3. 多引擎架构工程师；
4. Hamiltonian Path 算法接入工程师；
5. Windows 桌面软件工程师；
6. 授权系统集成工程师；
7. 自动化测试工程师；
8. 独立验收与质量保证工程师；
9. 工程文档和证据管理工程师。

你必须以正式软件工程项目的标准执行任务。

你需要理解：这个项目不是从零写一个哈密顿路径求解器，而是把已经存在的多个产品版本、研究原型、算法引擎、GUI、授权体系和历史验收成果，整合成一个稳定的统一产品。

**你的首要目标不是写代码速度，而是避免错误资产接入、错误算法语义、错误授权修改和错误验收。**

## 1.2 最终产品目标

最终交付：

`D03 解限版统合软件 v0.5`

它必须具备以下核心特征：

- 保留 v0.3 的完整 GUI 产品行为。
- 保留严格轨与广义 walk 双模式。
- 使用经过裁定的严格引擎完成真正的严格哈密顿路径求解。
- 使用现役广义 walk 引擎完成广义遍历任务。
- 统一不同算法的调用入口和结果状态。
- 对每个引擎输出进行独立验证。
- 保留原有授权体系和授权链。
- 保留13族显式构造能力。
- 正确处理无解、超时、错误和成功四种不同情况。
- 提供稳定的图输入、求解、验证、报告和导出流程。
- 不能把广义 walk 的结果包装成严格哈密顿路径。
- 不能伪造求解成功、性能数据或不可行性证明。

最终软件必须是一个完整的桌面应用，而不是若干独立 EXE 的简单集合。

- 目标：严格Hamiltonian Path；
- 每个节点恰好访问一次；
- 不允许重复节点；
- 每一步必须是原图中的真实边；
- 路径长度必须等于节点数；
- 必须通过独立严格验证器。

广义walk轨：

- 允许重复节点；
- 必须覆盖全部节点；
- 每一步必须是原图真实边；
- 不得使用虚构边；
- 不得显示为严格Hamiltonian Path成功；
- 必须使用独立walk验证器；
- 必须单独统计耗时、路径长度和覆盖率。

二者不能共享成功率指标。

不能在广义walk页面显示"哈密顿路径PASS"。

不能用walk结果填补严格轨无解结果。

- 输入位置是广义页面随机种子输入框；
- 支持FocusOut；
- 支持Return；
- 仅当前会话有效；
- 再次输入相同口令时关闭严格Tab；
- 不允许通过普通GUI按钮绕过授权逻辑。

## 6.2 未激活时严格Tab不得创建

未激活时：

- 严格Tab对象不能创建；
- 不能只是隐藏；
- 不能只是禁用；
- 必须通过`winfo_children`等对象树检查证明零痕迹；
- 必须检查对应子控件；
- 必须检查初始化过程没有提前创建严格页对象。

截图不能单独证明这个要求。

必须提供程序对象树检查结果。

## 6.3 授权与彩蛋联动

只有验签成功且授权未过期时，才能使用严格轨。

检查节点：

1. 输入彩蛋口令时；
2. 严格页显示期间每30秒watchdog；
3. 每次严格求解启动之前。

授权过期时：

- 只锁定严格层；
- 广义walk不受影响；
- 授权续期后恢复严格层；
- 不得退出整个软件；
- 不得破坏当前广义任务。

## 6.4 严格随机图规模门禁

严格页面通过随机生成方式产生的图：

`m < 10`

必须弹出提示，不启动严格引擎。

允许的例外：

- 图文件导入；
- 用户明确选择的13族显式构造；
- G1明确允许的其他构造入口。

必须明确区分随机生成和显式构造。

## 6.5 13族显式构造

保留13族构造入口。

具体数学定义、参数范围和限制，以G1：

`§二④`

为唯一正式依据。

每一族都必须具有：

- 参数输入；
- 图生成；
- 序列生成器；
- `is_real`边判定；
- 零断裂保证；
- 独立验证；
- 结果导出；
- 回归测试。

历史公式验证22/22 PASS只是历史基线，不能替代G2实际验收。

13族必须逐族测试。

不得为了统一代码而把13族入口合并成一个无法区分的通用按钮。

## 6.6 complete/walk/partial分账

必须保留三种状态：

- complete；
- walk；
- partial。

状态定义必须与G1一致。

不能把部分覆盖结果写成完整求解成功。

不能把walk结果写成严格路径。

## 6.7 导出协议

报告必须保留：

`[summary]`

`[verification]`

`[failed_edges]`

`[path]`

路径文件：

- 空格分隔；
- 每行10个节点；
- 末行允许不足10个节点；
- 不得混入解释性文本。

必须导出三件套：

1. 报告；
2. 路径；
3. 图文件。

优先保存到桌面。

桌面写入失败时使用TEMP目录兜底。

必须告诉用户真实保存位置。

## 6.8 授权产品隔离

保持：

`product_id='hamilton'`

72小时离线宽限：

- 以签名token中的ts为基准；
- 不得超过授权期；
- 不得使用本机随意修改的时间代替签名时间；
- 一用一废规则保持不变。

具体细节以授权正本为准。

## 6.9 客户界面信息保护

客户界面不得暴露：

- 内部算法常数；
- 虚拟边机制；
- 内部路由阈值；
- 引擎之间的内部切换策略；
- 不必要的内部目录；
- 密钥、token和签名细节。

具体脱敏列表以G1 §六-9为准。

## 6.10 预注册实验种子

保留：

- 广义m=3；
- 严格m=10；
- seed 1至100。

必须保证：

- 每个实验有独立记录；
- 不覆盖原始实验；
- 修改seed意味着新实验；
- 保存图指纹；
- 保存算法版本；
- 保存运行参数；
- 保存验证结果。
