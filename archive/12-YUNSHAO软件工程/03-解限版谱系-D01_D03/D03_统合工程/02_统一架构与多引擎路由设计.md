## 〇、设计边界与铁律（先立规矩再画图）

本设计只做架构与路由，不做算法重写。七条铁律贯穿全文：

1. **不为架构漂亮重写 v23_static**：v23_static.exe（74accc13f82e，784,261 B）与其谱系（v3x_m1v2 v2.3 静态正本）一律先适配封装。只有当适配层被证明无法弥补时，才在"改造建议"栏目提出（本件仅一处：无，即本件对 v23_static 零改造要求）。
2. **严格 HP 与广义 walk 永远分账**：不同问题、不同指标、不同验证器。walk 的成功（全覆盖+真边率+膨胀率）不得写成严格 HP 成功（每点恰好一次+0 断口）。统合图 v1.0 §二"禁止统合"第 1 条原样生效。
3. **求解器失败 ≠ 数学无解**：启发式超时/预算耗尽 = UNSOLVED（未出解），只有结构定理、BA m=3 定理判死、CP-SAT INFEASIBLE 证书三种来源才允许 INFEASIBLE_CERTIFIED。
4. **授权架构原样**：auth.pyd / 链验（CHAIN_MANIFEST）/ 激活流程（YS2- 密钥、产品域隔离、72h 离线宽限、一用一废）零改动。统合版对授权链的唯一动作="伴生件原样打包"。
5. **性能与内存数字只引在册值**：本件所有数字标注证据等级（甲/乙/丙/丁，定义见 §三），无在册出处的性能声明一律不写。已知禁引项：间隔抽查法 962 点数字（存证缺失，统合图 E-6）、LKH-3（无实物，E-7）、"m≥10 稠密 v3x 三秒级"（无在册出处，本件不采用该表述，改引 m=7@1e5 构造端 0.14-0.21 秒在册值）。
6. **判负域禁重开**：m4@1e5 pass 口径清零、更大 cap 加时、Φ 类势函数、G³ 升维、B2/B3 调度——整合设计书 §五"明确不做"清单原样生效，路由表不含这些通道。
7. **只读纪律**：本件为 G1 阶段交付，除本文件外未写任何文件、未改任何代码、未动任何二进制。

**版本账口径（承 G0 裁决）**：D03 在役产品正本=v0.3（905f7ba9d3a5，2026-08-18，双 Tab 彩蛋全功能壳）；v0.4 换芯版（26632d79443d，2026-11-08，v23_static 单引擎，激活链端到端已验收）；"v0.6"系误标禁用。统合版建议命名 **v0.5**（新件，不覆盖任何旧件，理由见 §七·D⑦）。

### 1.2 各层职责、输入输出与依赖方向

**依赖总方向：单向向下（L1→L10），L9 横切监督 L6/L7/L8，L2 是门不是变换。上层只依赖下层的接口契约，下层不知上层存在。禁止跨层调用（L1 不许直接调 L6 适配器——v0.4 融合壳 `_run_fusion` 直调 `_fus.route_strict` 的做法在统合版终止，改走 L2→L5 正道）。**

**L1 GUI 产品壳层**（行为基准=v0.3）
- 职责：双 Tab 布局（广义 Tab 常显、严格 Tab 彩蛋隐藏）、欢迎窗、进度条与状态栏、结果卡片、帮助窗、快捷键、热梗轮播、报告落点弹窗告知。
- 输入：用户动作（导图/生成参数/口令/按钮）。
- 输出：标准化求解请求（mode、图来源引用、N/m/seed）给 L2；渲染 L10 回传的结果。
- 依赖：L2（绝不绕过）。实现注意：所有求解在工作线程，GUI 主线程零阻塞（v0.4 融合壳已具此纪律，继承）。

**L2 模式与授权控制层**（授权架构原样，铁律 4）
- 职责：①启动门禁（auth.check_license，product_id='hamilton'，缓存→联网 verify→首用 activate→72h 宽限三态）；②彩蛋门（口令 /YUNSHAO-STRICT 大小写不敏感、先激活后彩蛋、未激活不创建 Tab 零痕迹、再输隐藏、会话级）；③时限联动（过期→严格入口消失+缓存许可失效+30 秒 watchdog 屏幕复查+运行前再复查；续期→恢复；过期只锁严格层，广义不受扰）；④m≥10 门禁语义（严格 Tab 对外部图/生成图默认要求平均度≥10，低于则提示走广义 Tab——v0.3 行为基准；显式构造 13 族豁免，见 §三 S-2）。
- 输入：求解请求+license 状态。输出：放行请求（附授权态）或拒绝。
- 依赖：auth.pyd（伴生件原样）、license.json（%APPDATA%\YS_HAMILTON 域不变）。

**L3 图数据标准化层**
- 职责：六格式（GraphML/GML/Pajek/Matrix Market/边列表/DIMACS）经 graph_formats.pyd 统一解析为内部表示；节点 ID 归一化（0/1 起始自动识别、有向转无向、权重忽略、重边合并、自环剥离并在指纹中记数）；孤立点保留（供全覆盖口径）；计算 graph_fingerprint（规范化边表排序后 SHA256+N/M/自环数，供日志与复现）。
- 输入：文件路径或生成参数。输出：标准图（n、边表、指纹、解析告警）。
- 依赖：graph_formats.pyd（链验伴生件，原样）。
- **修正项（承附录甲 #9）**：v0.4 融合壳的融合路径绕过 graph_formats 只吃原始边表，导致 GraphML 等五格式在融合模式下不可用。统合版 L3 统一供两条模式，此缺口关闭。

**L4 图结构预分析层**
- 职责：连通分量计数、度分布与平均度、度 1 叶子计数、**桥块树**（把每个双边连通块缩为一点、桥为边）构造与奇度点计数、图族识别（自生成 BA 族直接带 m；外部图以 m_proxy=平均度/2 作 BA 族启发式代理，仅用于路由不用于结论）、必要条件冲突判定。
- **无解证书的保守必要条件集（本件修正，见附录甲 #1）**：
  - EMPTY（空图）、DISCONNECTED（不连通）；
  - DEG1_GT2（度 1 叶子>2——路径只有两个端点，每个叶子必须占一个）；
  - BRIDGE_TREE_NOT_TRACEABLE（桥块树奇度点>2——每条桥恰好被路径跨一次，故路径在桥块树上的块序列是一条用尽全部桥的欧拉通路；树有欧拉通路当且仅当奇度点≤2。此判据数学上严格，且比融合引擎 v0.1 的 BRIDGE_SPLITS_GE3 弱——后者是**过强判据，会报假无解**，反例：两个三角形用一条桥相连，删除桥后两分量各 3 点，v0.1 判"无解"，但路径 a→b→u→v→c→d 就是合法严格 HP）。
- 设计原则：**预检宁漏勿误**。只判"确证无解"，拿不准的一律放行给路由层（烧算力好过报假无解——D03 规格验收 7"无解图不许硬凑假路径"的反向对偶：有解图更不许硬判无解）。
- 输入：标准图。输出：特征档案+预检结论（证书文本或放行）。

**L5 求解器路由层**
- 职责：执行 §三路由决策表；把预算切分为各引擎的 per-engine 超时；维护失败后备链；产出路由轨迹 trace。
- 输入：放行请求+标准图+特征档案。输出：引擎调用单序列；最终汇总裁决交 L9/L10。
- 依赖：L6 适配器注册表（引擎可用性探测：文件存在+版本哈希核对）。

**L6 多引擎适配层**
- 职责：每引擎一个适配器，统一契约（输入：标准图文件+参数+预算+seed；输出：SolveResult 原生口径）；统一资源定位（打包随件优先 sys._MEIPASS，禁硬编码本机绝对路径——修正承附录甲 #5）；统一子进程宿主（见 §四·D⑥）；版本哈希登记进 solver_id。
- 现役五适配器+一直写器：hamilton_engine.pyd（Ed25519 验签，solve_licensed）、v23_static.exe、分图而治 v2.5、walk_engine.dll、SAT 裁判（CP-SAT AddCircuit）、13 族显式构造直写器。
- 依赖：L4 特征档案（路由已定，适配器不做二次决策）。

**L7 分块与缝合层**（预留槽）
- 职责（目标态）：统一 stitch 接口+分块器路由（hub 辐射/间隔带/胶囊/整图，按图族×规模×直径选分块器）——统合图 v1.0 §四 P0 判定。
- G3 阶段现实：分图而治 v2.5 内部自带"主路径+剩余图分片+缝合"，本层暂由其内部承担，对外不暴露分块接口。间隔带分块器因存证缺失（E-6，证据等级丁）**不进本层**。
- 依赖：L6（片内求解器黑盒化，统合图 §二"路由统合"判定）。

**L8 修复与优化层**（预留槽）
- 职责（目标态）：统一 move cascade（统合图 P3，证据不足暂缓）。G3 阶段现实：修复由各引擎内部承担（v3x 的 D2/13 类移动、分图而治的残留修复、pyd 的 LNS/RR/opt3/neutral）。本层实际承担：预算调度（B1 等额交付语义由 v3x 内部承担）、超时升级、"继续求解"（预算加倍重跑，v0.3 壳在册行为）、降级 walk 建议。
- 依赖：L5（调度指令）、L6（引擎能力）。

**L9 独立验证层**（横切，强制）
- 职责：严格口径=三关甲（长度=N ∧ 无重复 ∧ 全真边，verify_hp 纪律 87/87 与引擎零分歧在册）；广义口径=verify_walk（全覆盖 ∧ 真边率 ∧ 膨胀率复算——**D03 规格 R2 在册要求，现无实物，G4 新建**，修正承附录甲 #3）；证书口径=SAT INFEASIBLE 与定理判死的证书落盘。
- 铁律：runner≠judge。任何引擎自报"成功"未经本层一律不作数；walk 结果永不过三关甲（L==N 硬校验不兼容 walk 语义，D03 规格 R2 原话），strict 结果永不用 verify_walk。
- 依赖：verify_path.py/verify_path2.py（随包 datas，v0.4 spec 在档）、裁判甲（打包边表）/裁判乙（CSR 扫描）在档件。

**L10 结果日志报告层**
- 职责：四态结果组装（§二）；trace jsonl 逐例落盘（引擎、耗时、验证、错误——增量写，进程崩溃不丢已跑轨迹）；报告+路径文件+图文件三件导出（桌面优先、TEMP 降级，v0.3 壳在册行为）；落点弹窗告知。
- 输入：L9 验证结论+L5 trace。输出：SolveResult 终稿+文件落点。

## 二、B 节：统一求解接口与四态语义

### 2.1 请求对象

```
SolveRequest:
  graph:
    n: int                          # 节点数（含孤立点）
    edges: [(u, v), ...]            # 标准化后边表（L3 产物，原始 ID 空间保留映射）
    source: "generated_ba" | "file" # 生成图带 family_hint={"ba": {"m": m}}；外部图 m=None
  objective:
    mode: "strict" | "walk"         # 严格 HP / 广义走行——分账根字段
    require_certificate: bool       # true 时小图追加 SAT 无解证书通道
    prefer: "auto" | "construction" | <engine_id>   # auto=路由表；construction=优先13族直写
  budget:
    total_seconds: float            # 总预算，耗尽→停→UNSOLVED
    per_engine_seconds: {engine_id: 秒}   # 缺省沿用融合引擎 v0.1 在档默认：分图而治900s / v3x 1800s / 验证120s
  seed: int                         # 贯穿生成与引擎，结果回填实际生效值
  options:
    verify_level: "always"          # 默认恒开；"off"仅实验通道（allow_research=true）可用
    output_dir: 路径                # 缺省桌面优先/TEMP降级
    allow_research: false           # 研究引擎实验通道总闸（§五）
    engine_override: null           # 显式指定引擎 id（实验通道专用）
```

### 2.2 结果对象

```
SolveResult:
  status: "SOLVED" | "UNSOLVED" | "INFEASIBLE_CERTIFIED" | "ERROR"
  path: [原始ID空间节点序列] | null
  solver_id: "engine@版本哈希前12位"   # 如 v23_static@74accc13f82e；多引擎接力=最终出解者，trace 记全程
  graph_fingerprint: "sha256:<规范化边表指纹>|N=<n>|M=<去重边数>|loop=<自环数>"
  runtime: 秒（总耗时）
  seed: 实际生效种子
  coverage: 严格=path_len/N（SOLVED 时恒=1.0）；walk=unique_nodes/N
  duplicates: 严格=重复节点数（SOLVED 时恒=0）；walk=path_len-unique_nodes
  breaks: 断口数（相邻步非真边计数）；严格 SOLVED 时恒=0；walk 如实报告
  verification_status: "PASSED"(三关甲/verify_walk) | "CERTIFIED"(SAT证书/定理) | "FAILED" | "NOT_APPLICABLE"(仅ERROR态)
  log_path: trace jsonl 路径 + 报告文件路径
  trace: [{engine, ok, elapsed, verify, err}]   # 路由轨迹，逐引擎如实
  note: 诚实边界说明文本（如 m4@1e5 定格、m=3 定理判死缘由）
```

### 2.3 四态严格区分（判定矩阵）

| status | 进入条件 | 禁止事项 |
|---|---|---|
| **SOLVED** | path 非空 **且** L9 独立验证 PASSED（严格：三关甲全过，即 coverage=1.0、duplicates=0、breaks=0；walk：全覆盖+真边率 100%，膨胀率如实） | 未经独立验证的引擎自报成功禁止标 SOLVED；walk 成功禁止写成严格成功 |
| **UNSOLVED** | 启发式穷尽/超时/预算耗尽/引擎链走完无验证通过解 | **禁止写成无解**；禁止外推为"该图不存在 HP"；必须附 trace 与建议（加预算重试/降级 walk） |
| **INFEASIBLE_CERTIFIED** | 且仅三种来源：①L4 保守必要条件集命中（EMPTY/DISCONNECTED/DEG1_GT2/BRIDGE_TREE_NOT_TRACEABLE）②BA m=3 定理判死（容量流 KILL+K2 交付双确认在册）③CP-SAT INFEASIBLE 证书（小图） | 三种之外的一切"猜测无解"禁止进入本态；证书文本必须落盘 |
| **ERROR** | 引擎缺失/崩溃/未授权（solve_licensed 返回 unauthorized）/IO 失败/适配器契约违例 | 禁止与 UNSOLVED 混淆（基础设施问题≠求解失败≠无解）；必须可重试 |

**典型场景对照**：m=3 BA 图→INFEASIBLE_CERTIFIED（定理判死，0 秒，不烧算力）；Crown-10（度 1 叶 10 个）→INFEASIBLE_CERTIFIED；m4@1e5 BA→UNSOLVED（pass 口径 0/6 定格在册，如实报，note 写明"移动-构型匹配缺口，构型性非算力"）；walk_engine.dll 文件缺失→ERROR；v3x 1800 秒超时→trace 记录后转下一引擎，全链尽→UNSOLVED。

- **现状分层**：exe 引擎（v23_static/分图而治 EXE/solver_verify）已是子进程调用，天然隔离——继承。风险集中在两件**进程内**载体的调用：hamilton_engine.pyd（importlib 进程内加载）与 walk_engine.dll（ctypes 进程内调用）——崩溃（访问违例）会带走整个 GUI 进程，v0.4 融合壳正是这么接的（route_strict 在 GUI 工作线程内直接跑 pyd/dll）。
- **统合设计**：建一个极薄**引擎宿主 EXE**（eng_host：PyInstaller console 小件，从 build_v03 现成构建链出，spec 九代在档——整合设计书 §五.1 原话"构建链现成"，属封装不属于重写），进程内只做 pyd/dll 加载与文件进出，stdin/stdout/文件传结果；主壳经子进程调它。宿主崩溃=该引擎 ERROR+后备链继续，GUI 无感。
- **降级通道**：宿主构建失败时，退回工作线程+faulthandler+watchdog（超时强杀标记 ERROR+trace 已增量落盘不丢）+结果文件即时 flush——不优雅但可用，作 G3 应急位。
- **GUI 纪律**：主线程零求解；停止按钮=kill 子进程（v0.3 在册行为）；任何引擎无响应超预算→ERROR。

### D⑦ 旧版回滚

1. **版本策略**：统合版=v0.5 新件新名，**不覆盖任何旧件**——桌面 v0.3 正本（905f7ba9）与其同哈希备份（pre_replace）原样不动；v0.4 换芯版（26632d79）留 dist_v04 正式位；三件并存可随切。

3. **触发条件**：G5 验收门未过 / 激活链异常 / 上线后严重回归（崩溃、假无解、分账混淆任一）。
4. **回滚演练**进 G6 门：卸载/覆盖/回切三步在测试机走通后才交付。

## 附录甲：对融合引擎 v0.1 的继承与修正清单

**继承（骨架原样）**：路由树四段结构（预检→稠密 pyd→分图而治→v3x→兜底）；walk_engine.dll ctypes 接线签名；三关甲判据与进程内等价实现；BA 重建口径生成器 _gen_ba_rebuild（正本口径）；严格门禁口令与授权文件校验逻辑；诚实汇报语（无解证书/如实报不伪造/严格与 walk 分账意识）；frozen 环境适配经验（_MEIPASS、fenzhi 子进程化修卡死、verify 进程内化）。

**修正（九项，每项含理由）**：
1. **桥判据假无解**：BRIDGE_SPLITS_GE3 过强（两三角一桥反例，见 §一 L4）→改桥块树欧拉通路判据。理由：报假无解违反验收 7 的对偶原则，且损害"证书"二字的可信度。
2. **分图而治适用域误标**：其 EXE 接口仅自生成 BA（--N --m --seed），对导入边表解的是另一张图，验证必 FAIL 白烧 900s→路由表 S-3 限定自生成族+边表改造候裁。理由：适配器必须"解用户给的图"，不是"解一张像的图"。
3. **walk 无独立验证**：R2 在册要求的 verify_walk 缺位→G4 新建为 SOLVED 硬门。理由：runner≠judge 制度对广义同样适用。
4. **进程内调用崩溃面**：pyd/dll 在 GUI 工作线程内直跑→引擎宿主子进程隔离。理由：引擎崩溃不应等于产品崩溃。
5. **硬编码绝对路径**：hermes/H 盘本机路径→统一资源定位+缺件即 ERROR。理由：可分发性与可测试性。
6. **二元结果模型**：v0.1 只有 ok/no_solution，ERROR 与 UNSOLVED 混淆、启发式失败与数学无解边界模糊→四态模型（§二）。理由：四态是"求解器失败≠数学无解"铁律的接口化。
7. **指纹与轨迹未标准化**：trace 在内存 JSON、报告导出靠 GUI 手拼→graph_fingerprint+trace jsonl 增量落盘标准化。理由：复现、对账、崩溃不丢账。
8. **seed/预算散参**：函数参数散传→进 SolveRequest 结构化对象。理由：验收预注册（seed 清单不可变）需要结构化载体。
9. **标准化层旁路**：融合路径不吃 graph_formats 六格式→L3 统一供两模式。理由：用户拿 GraphML 来不该被提示换边列表。

**另记**：v0.4 融合壳为中间产物（G0 定案），其 GUI 层不直接进统合版，但其工作线程纪律、报告三件导出、桌面/TEMP 降级、继续求解加倍预算四处 UI 行为被 L1/L8/L10 继承。
