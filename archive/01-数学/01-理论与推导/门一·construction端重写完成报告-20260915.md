## 二、本轮实现（door1_construction_v2）

### 2.1 构造端
1. **Warnsdorff 双端延伸**：每步从路径端点选"未访邻居数最少"的后继（0905 逆向机制；对 BA 图天然先走叶子后走 hub）；
2. **Pósa 深度旋转链**（posa_deep）：双端卡住时链式旋转（旋转保合法性、无需回滚），直到链端出现未访出口，深度 60；
3. **最小断口强插**（force_splice）：全扫描选残余点（随机采样会以 ~13% 概率整批漏掉最后几个顶点——本轮实际踩到并修复的 bug），插到新增断口数最小的槽位。

### 2.2 修补端（repair，五类移动迭代至不动点）
- **A 断口对互修**（2-opt）：两断口 i,j 若 (p[i],p[j]) 与 (p[i+1],p[j+1]) 均为真边，反转 [i+1,j] 一次消两断；
- **B 单断口缝补**：扫断口端点邻居找第三个连接点，反转缝补；
- **B2 端点缝合**：断口端点与路径首/尾相邻时 prefix/suffix 反转；
- **R 定向旋转缝合**（本轮关键增量）：对断口在后缀/前缀内走 Pósa 旋转链（800 步 × 5 个随机流），链端一旦撞上断口端点的邻居即一次反转缝合——**这是 9 断口 → 0 的决定性移动**；
- **LNS 扰动**：随机旋转链扰动 → 修补 → 择优保留（300 轮兜底）。

### 2.3 验证纪律
每案例独立严格验证：排列完整性（无重无漏）+ 相邻对全真边 + 断口计数双口径。PASS 当且仅当三关全过。

## 六、工程教训（本轮实踩）

1. CP-SAT/or-tools 无关——纯 C++；`pywraplp.Solver.OPTIMAL` 类 API 坑不适用；
2. 随机采样强插在残余顶点 <0.2N 时整批漏采（P(0命中)≈13%）→ 必须全扫描；
3. 部分"完整度 99%"的路径断口可以为 0——选择准则必须**完整性优先于断口数**；
4. 旋转链的正确用法是**链式走到出口**（保合法性无回滚），而不是"试 N 步不行就回滚"；
5. Windows Git Bash 下 python 写 C++ 字符串含 `\n` 会被 JSON 转义降级为真换行——用 chr(92)/chr(10) 规避。
