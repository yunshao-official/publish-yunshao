## 1. 整理方案：为什么这样整理

### 1.1 五层结构

```
L0 正本层   00-正本（裁决/常数/公式总表）
            内部版/<各册最新版>（9 册正文）
            03-论文与对外（对外定稿）
L1 成果层   05-索引/数学成果索引（本件，按成果而非文件组织）
L2 证据层   02-实验与数据（预注册/执行报告/结果）
            04-工具与代码/results（脚本+JSON+sha256 锁箱）
L3 版本层   05-索引/数学版本链（34 个多版本族，自动取最新）
            09-归档 / 归档-旧常数体系（只读，不作现行口径）
L4 工具层   04-工具与代码（代码/引擎/概念宇宙构建脚本）
            05-索引/_build_math_index.py、_build_results_index.py
```

### 1.2 四条规则

1. **成果≠文件**：一个成果常跨“正本+判据+执行报告+结果 JSON”四件。索引以成果为主键，证据列给路径与章节；文件总表另存，二者用路径关联。
2. **状态先行**：每条成果必须带状态。判负、冻结、不可检验都是一等公民，不藏在正文里。
3. **版本链归并**：同族按 `vX.Y` 与日期取最新；旧版不删，只在版本链里标为历史。当前 34 个多版本族，最长的是 代数册·12组完全分辨签名族立项书（28 版）、黎曼猜想·通俗图解（15 版）。
4. **物理不动**：本次只新增 `05-索引` 下的索引文件；原目录结构、文件名、归档位置全部不动。需要重排时另开迁移案，不混在索引里做。

### 1.3 命名与落位（新增成果时）

- 正本/裁决 → `00-正本/`；推导/判据/执行报告 → `01-理论与推导/`；实验数据 → `02-实验与数据/`；对外稿 → `03-论文与对外/`；代码与结果 JSON → `04-工具与代码/`；索引 → `05-索引/`。
- 文件名建议：`主题·成果名-vX.Y-YYYYMMDD.md`；预注册件加 `预注册`，负结果在标题或状态里写明。
- 新增后在 `_build_results_index.py` 的 `ENTRIES` 追加一行，重跑脚本即可同时更新 CSV/JSON/Markdown。
